# V63 — PostgreSQL fresh schema

PostgreSQL now has its own **single current schema**, created through the
internal `PostgresBackend::createSchema` method. The caller is responsible for
starting a write transaction and rolling back on any failure; schema creation
uses no legacy migration steps and creates no objects if that transaction is
rolled back.

The schema mirrors SQLite's current 23 tables, 13 indexes and 52 guards,
plus PostgreSQL's case-insensitive username/group-name unique indexes.
It uses PostgreSQL native `uuid` for UUID fields and `bytea` for hashes,
serializations, binary tokens and snapshots. Integer columns are `bigint`:
SQLite's `INTEGER` is signed 64-bit, unlike PostgreSQL's 32-bit `INTEGER`.
The audit sequence uses `BIGINT GENERATED BY DEFAULT AS IDENTITY`.

Because the AOWIS project/branch/revision tables refer to each other, the
PostgreSQL schema creates tables first, then foreign-key constraints, then
indexes, then PL/pgSQL guard functions and triggers. All 52 SQLite trigger
purposes are represented. Revocation guards use PostgreSQL's null-safe
`IS [NOT] DISTINCT FROM` in place of SQLite `IS [NOT]`. Session redaction
constructs the unchanged byte sequence from the token prefix plus the UUID's
RFC-4122 bytes using PostgreSQL `decode`.

`verifySchema` checks the presence of every expected application table,
index, foreign key and trigger by name. It is not a proof that a database administrator
hasn't maliciously modified trigger bodies. As with SQLite, the administrator
is trusted and may alter database structures.

## Testing

The existing SQLite tests continue to run without PostgreSQL. For an optional
live smoke test, supply `AOWIS_DB_TEST_PG_DB` and appropriate `PGHOST`,
`PGUSER` and libpq credentials, including privileges to create a schema in
the **test database**. The backend-contract test then creates the complete
PostgreSQL schema inside its own transaction, checks column types, validates
an attribution guard and rolls the transaction back. It leaves no permanent
schema changes. **Do not point this test at a production database.**

## Deliberate limitation

`Database::openSqlite()` is still the only public connection method. The
remaining domain queries have not been validated against PostgreSQL and may
contain SQLite-only syntax. V63 only establishes a guarded PostgreSQL schema;
PostgreSQL is **not production-ready or available through the public API**.
The future INI will use Qt `QSettings` and `QStandardPaths`, include an
`AOWIS_DB_SERVER_MODE` path switch and allow overriding default database/log
paths. It is intentionally not part of this schema patch.
